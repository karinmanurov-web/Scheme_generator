# Regression harness

Цель контура — прогонять четыре уже реализованных алгоритма без AutoCAD и не давать новой итерации кода повторно ломать рабочие случаи.

## Быстрый запуск

Из корня репозитория:

```bash
python -m pip install -r tests/requirements.txt
python tests/run_regression.py
```

Только один case:

```bash
python tests/run_regression.py --case piles
```

Только семантические/структурные проверки без рендера:

```bash
python tests/run_regression.py --no-render
```

Результаты появляются в `reports/` и не коммитятся:

- `reports/report.json` — машинно-читаемый результат;
- `reports/report.html` — человеко-/AI-читаемый отчёт;
- `reports/<case>/result.dxf` — сгенерированный DXF;
- `reports/<case>/result.png` — headless preview;
- `reports/<case>/reference/page_XX.png` — страницы эталонного PDF.

## Как устроен case

Каждый `tests/fixtures/<case>/manifest.yaml` явно связывает:

- исходный DXF;
- эталонный PDF;
- Python-модуль и функцию алгоритма;
- количество листов PDF;
- автоматические структурные проверки;
- пока ещё ручные проверки, которые будут постепенно превращаться в автоматические.

Важно: автоматические проверки относятся к **результату генератора**. Они не требуют конкретных имён слоёв или блоков в исходном DXF. Допустимые варианты выходных слоёв задаются только там, где это часть контракта самого генератора.

## Уровни проверок

1. **Execution** — алгоритм запускается и создаёт DXF.
2. **DXF integrity** — результат открывается `ezdxf`.
3. **Structure** — есть достаточная геометрия, текст и необходимые выходные слои.
4. **Semantic contract** — проверяются роли вроде проектных/фактических размеров и рамки.
5. **Visual review** — результат и все страницы эталона рендерятся в PNG и попадают в HTML-отчёт.
6. **Manual checks** — пока отображаются как checklist; это сознательно, чтобы не зацементировать ошибочные правила.

Следующий этап — заменить ручные проверки на специализированные evaluators для геометрии, числовых данных, таблиц, координат и визуальных признаков.
